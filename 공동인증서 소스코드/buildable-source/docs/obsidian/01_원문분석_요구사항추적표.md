# 원문 분석과 요구사항 추적

전체 설계서의 다기관 신뢰 플랫폼과 추가 설계서의 원격판독 UX를 통합한다. 아래 요구사항 ID는 구현 티켓과 시험 ID의 연결 기준이다. 원문의 후보 기술을 최종 채택 기술과 혼동하지 않는다.

## 원문과 해석 범위

- A: [Inviz Medical Sign Architecture 2026](file:///C:/Project/Vision-Certi/Inviz_Medical_Sign_Architecture_2026.pdf), 4쪽, 2026-10-12, v1.0. 환자 동의와 원격판독을 포괄한다.
- B: [원격판독 인증 전자서명 추가 설계서](file:///C:/Project/Vision-Certi/Inviz_RemoteReading_Authentication_Esignature_Addendum_2026-10-12.pdf), 5쪽, 작성일 2026-10-12. 원격판독 인증·승인 동작을 구체화한다.
- 사용자 결정: 원격판독 우선, Java/Spring, 인비즈 중앙 서버, 공급자 미정, 의사 서명 전용 화면, 상용 확장 규모.

원문의 T Cloud Care, Cloud Care Life, CCL 표기는 공급자가 같은 제품인지 확정되지 않았다. 내부 문서에서는 Cloud Care로 부르고 제품·버전 매핑은 EXT-001에서 확인한다.

## 원문 차이의 해결

| 주제 | 원문 차이 | 채택 정책 |
|---|---|---|
| 인증 | A의 approve 설명은 재인증, B는 위험 시만 재인증 | 매 건 명시적 승인, 위험 시만 MFA 추가 |
| 고정 시점 | B p3에서는 클릭 후 문서 고정 | 열람 전에 고정하고 승인할 때 버전·해시 일치 검사 |
| 시각 | B는 서버 시각과 필요시 신뢰 시각, A는 장기 검증 | 운영 완료 조건에 검증된 RFC 3161 증거 포함 |
| 문서 형식 | A는 PAdES/CMS/JWS 후보 | v1 PDF 원본＋분리형 CAdES, PAdES는 별도 확장 |
| HSM/KMS | B는 HSM 또는 동등 KMS | 비수출·사용자별 키·승인 결속을 입증한 구현만 운영 허용 |
| 법적 지위 | 자체 구축과 평가인정 구분 | 법률·병원 승인 없이 인증사업자 또는 EMR 인증 취득 표시 금지 |
| FINAL | 외부 최종판독과 내부 서명 상태 혼재 | 외부 상태와 내부 서명·증거·전송 상태 분리 |

위 정책은 원문 인용이 아닌 구현 결정이다. 상태·보안 정책 변경은 [[11_외부의존성_결정대장]]에 남긴다.

## 공식 검토 자료

- [의료법 제23조 원문 참조 링크](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032321715): A p4가 제시한 자료. 실제 적용 시점의 시행 조문·부칙은 법무 담당자가 다시 확인한다.
- [전자서명법 원문 참조 링크](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=236201): 자체 서비스의 의무·평가인정 해당 여부 검토 자료.
- [EMR 인증기준](https://emrcert.mohw.go.kr/evaluateWeb/evaluateInfoList.es?mid=a10102020000): 2026(v1.2) 요구사항과 구현 증거 매핑 기준.
- [Spring 시스템 요구사항](https://docs.spring.io/spring-boot/system-requirements.html): Java/Spring 호환 검토.
- [PostgreSQL RLS](https://www.postgresql.org/docs/18/ddl-rowsecurity.html): 기관 격리와 소유자 우회 방지 설계.
- [RFC 3161](https://www.rfc-editor.org/info/rfc3161/): 타임스탬프 생성·검증 기준.
- [OASIS PKCS 11](https://docs.oasis-open.org/pkcs11/pkcs11-spec/v3.1/os/pkcs11-spec-v3.1-os.html): HSM 접근 어댑터 기준.
- [DSS 개발 문서](https://ec.europa.eu/digital-building-blocks/DSS/webapp-demo/doc/dss-documentation.html): CAdES·검증·장기 증거 구현 기준.

기술 문서의 규격 지원이 국내 법적 효력·의료기관 인증을 보장하지 않는다. 법적 보존기간과 운영 책임은 LEGAL-001에서 확정한다.
