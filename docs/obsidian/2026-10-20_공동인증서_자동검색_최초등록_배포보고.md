# 공동인증서 자동 검색·PACS 최초 등록 배포 보고

## 결과

- `https://vision-certi.web.app`의 인증서 창에서 하드디스크/이동식디스크를 선택하면 **현재 PC**의 로컬 인증서 프로그램에 해당 저장매체 검색을 요청한다. 브라우저가 시스템 폴더 열기를 거부해도 설치·브라우저 권한·재검색 안내가 나온다.
- Windows x64 설치 ZIP: `https://vision-certi.web.app/downloads/vision-certi-bridge-win-x64.zip`. SHA-256: `ecf6797cb37002c9db3717b58fd269a92323fe74b5a9ac7c39036222f9cb0900`. 각 의사 PC에서 압축을 풀고 `Install.cmd`를 1회 실행해야 한다. 실행 파일은 현재 사용자 영역에 복사되며 Windows 로그인 시 자동 시작한다.
- 현재 PC에서 설치 파일의 내용 해시 검증, 설치, 시작프로그램 바로가기 생성, 하드디스크 인증서 **8건** 검색을 확인했다. 이동식디스크는 당시 검색 결과 **0건**이었다. 허용되지 않는 폴더와 안전 탐색 한도(깊이 16, 폴더 10,000개, 인증서 200개)는 자동 검색 대상에서 제외될 수 있다.
- PACS 최초 연결은 PACS ID/PW로 계정을 확인하고 인증서 소유 증명, 면허·자격 정보, 동의가 끝나면 서버에 계정·인증서 연결을 저장한다. 승인 전 상태는 `PENDING`이며, 이후 활성 상태가 된 인증서로만 단독 로그인이 된다. 인증서 비밀번호와 개인키는 PACS·인증서버에 저장하지 않는다.
- PACS 로그인 화면에는 첫 사용 시 ID/PW로 진행하는 방법을 표시했다. 미등록 인증서로 단독 로그인을 시도한 팝업에도 최초 등록 경로를 안내한다.

## 적용 대기와 경계

- 현재 실행 중인 Saintview PACS 백엔드의 `/api/vc/config`는 여전히 `passwordLoginRequiresCertificate=false`를 반환했다. `backend/.env`에 `VISION_CERTI_PASSWORD_LOGIN_REQUIRES_CERT=true`를 기록했지만 **백엔드 재시작 전에는 반영되지 않는다**. 실행 중 프로세스의 재시작은 자동 실행 정책에 의해 거절되어 완료하지 못했다.
- 현재 PACS 개발 설정은 로컬 `127.0.0.1:18082`, 데모 기관 `demo-hospital-a`를 가리킨다. 운영 웹은 별도 클라우드 PostgreSQL의 `inviz` 기관을 사용하므로 이 두 환경의 등록 기록은 공유되지 않는다. 운영 PACS를 연결할 때 HMAC 비밀을 서버에서 안전하게 설정하고 `VISION_CERTI_BASE_URL`/`VISION_CERTI_PUBLIC_BASE_URL`을 모두 `https://vision-certi.web.app`으로 맞춰야 한다. Saintview 클라이언트가 `/v1`을 자동으로 붙인다.
- 다른 PC의 실제 브라우저·USB 인증서와 PACS 계정 최초 등록 종단 간 검증은 아직 수행하지 못했다. 브라우저의 로컬 네트워크 접근 허용이 필요하며, 사용자가 각 PC에서 설치 후 **다시 검색**을 눌러 확인해야 한다. 의료인 면허 검토 및 임상 판독 권한은 별도 승인 대상이다.
