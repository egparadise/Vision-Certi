# 개발 작업과 선행 조건

작업은 산출물과 시험 증거로 완료한다. 아래 표는 전체 제품 목표이며 현재 개발용 slice와 구분한다. 초기 코드는 일부 UI·API를 확인하기 위한 것이고 운영 인증·HSM·DB 통합을 대체하지 않는다.

## 공통 완료 정의

표의 진행 대상은 완료가 아니다. 실행 중 상태와 결과는 개발 보고서에 기록하고 검토 후 표를 갱신한다. BE-001 전체 OIDC 구현 전에 명시적 개발 프로파일로 BE-003 mock slice를 먼저 검증할 수 있으나 운영 완료로 계산하지 않는다.

## 병렬 진행

P0에서 Codex가 계약과 DB·개발환경을 만들고 Claude/antigravity는 각 앱 골격을 만든다. 계약 초안이 고정되면 Claude는 API를, antigravity는 동일 응답의 mock UI를 개발한다. 두 담당이 같은 파일을 동시에 수정하지 않는다.

서명 핵심을 통합한 뒤 인증서·전송·검증을 병렬 완성한다. 성능 시험은 모의 공급자 수치와 실제 HSM/TSA 수치를 분리한다. P4는 EXT-001~005, LEGAL-001, OPS-EXT-001 해결 후 종료한다.

## 작업 인계 형식

각 보고서는 작업 ID, 수정 파일, 계약 버전, 실제 실행 명령과 종료 코드, 통과·실패·미실행 시험, mock·운영 제한, 다음 담당을 포함한다. 완료 주장은 로그·테스트 리포트·실제 파일로 확인한다.

Orca의 대기·heartbeat는 완료 증거가 아니다. Claude와 antigravity는 각자의 Task/Dispatch로 질문·진행·완료를 보고한다. 작업 전달이 차단되면 전달 완료라고 표시하지 않는다.
