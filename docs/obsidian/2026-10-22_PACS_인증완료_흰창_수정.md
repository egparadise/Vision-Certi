# 확인한 원인

SaintViewPACS 3.40.4에서 인증 페이지가 정상 로드되고 `window.opener`도 존재함을 확인했다. 그러나 부모 PACS가 `popup.close()`를 호출하면 WebView2 내용만 종료되고 바깥 네이티브 창이 흰색으로 남았다. 설치된 앱에서 직접 호출해 사용자가 제보한 현상을 재현했다.

# 수정

- 웹: 인증 결과 전송 후 **인증되었습니다.**와 **PACS 화면으로 돌아가기** 버튼을 표시한다.
- PACS: 정상 결과 수신 시 이벤트 리스너와 타이머만 정리한다. 성공한 인증 창을 자동으로 닫지 않으며, 이후 PACS 로그인 오류도 완료 화면을 지우지 않는다.
- 잘못된 서명, 잘못된 비밀번호, 유효하지 않거나 만료된 응답에는 완료 화면을 표시하지 않는다.
- Vision-Certi는 인증서 검증 결과 전달까지 담당한다. PACS의 계정 로그인과 판독 승인은 PACS의 역할이다.

PACS 소스: `egparadise/Saintview-Web-PACS`, 기준 `기능-개선`의 `0c08163`, 수정 브랜치 `fix/certificate-completion-window`, 커밋 `a8813a7`, 버전 **3.40.5**.

# 직접 검증

| 검증 | 결과 |
| --- | --- |
| 웹 인증·인증서 파일·PC 프로그램 연동 테스트 | 4개 파일, 23개 통과 |
| PACS 브로커·로그인·연결 주소 테스트 | 3개 파일, 20개 통과 |
| 실제 네이티브 PACS에서 기존 `popup.close()` 재현 | 웹 내용 종료 후 흰 외곽 창 확인 |
| 수정 화면에서 잘못된 인증서 비밀번호 | 거절, 결과 미전송 |
| 올바른 시험 비밀번호 및 실제 개인키 서명 검증 | 성공 |
| 요청 PACS의 일회용 코드 수신 | 정확히 한 번 수신 |
| 결과 전송 뒤 완료 화면 유지 | 확인 |
| 배포된 Firebase 정적 파일을 사용하는 네이티브 회귀 시험 | 통과 |
| 최종 3.40.5 실행 파일 내장 화면 + 배포된 웹 정적 파일 | 동일 회귀 시험 통과 |

회귀 스크립트: `tests/browser/native-completion.cjs`. 임시 인증서와 시험 비밀번호를 사용해 암호화된 개인키 복호화·서명을 실행하고 공개키로 검증한다. API 응답과 PACS 브로커는 격리하며 실제 PACS 계정 로그인은 수행하지 않는다. 사용자의 실제 인증서 비밀번호를 입력·수집하지 않았다.

웹 화면은 `https://vision-certi.web.app`에 배포했다. 기존 PACS 3.40.4의 자동 닫기 코드는 웹 배포만으로 제거되지 않으므로 해당 클라이언트를 수정본으로 업데이트해야 한다.

## 다른 PC 적용

1. PACS를 종료한다.
2. [SaintViewPACS 3.40.5 설치 파일](https://vision-certi.web.app/downloads/saintview-pacs-3.40.5-setup.exe)을 다운로드하고 실행한다.
3. 설치 후 PACS를 열어 공동인증서 로그인을 시작한다. 비밀번호 확인에 성공하면 아래 완료 화면이 남아야 한다.

설치 파일은 171,459,232바이트이며 SHA-256은 `59029882fa5839ae34f4bd890a1fa17003fc85dd1716d3f0b269c8b20a7167f5`다. 빌드에는 기존 설치본의 인증 브로커와 음성 인식 리소스를 그대로 포함했다. 다른 PC의 실제 계정 로그인·설치 완료까지 원격 확인한 것은 아니다.

배포 주소에서 설치 파일을 다시 다운로드해 크기와 SHA-256 일치를 확인했다. 실제 네이티브 창의 접근성 트리에서도 완료 제목과 PACS 복귀 버튼을 확인하고 위젯이 보이는 화면을 저장했다.
