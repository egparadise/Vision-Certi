# 구현·검증 현황 — 2026-10-15

## PACS 최초 등록 변경

PACS에서 기존 ID·비밀번호를 확인한 뒤 공동인증서 최초 등록을 시작합니다. 관리자 일괄 사전등록과 초대코드 입력은 필요하지 않습니다. PACS DB의 계정·성명·면허·소속을 서버 간 HMAC으로 전달하고, 인증서 서명·폐지 검증, 본인 동의, 인증서와 의사 정보 연결 검토를 거쳐 활성화합니다. 이후 비밀번호 로그인에서는 등록 상태를 재검증합니다. 미등록·정지·폐지 상태는 캐시된 세션에서도 일반 PACS API 접근을 차단합니다.

이번 변경 검증: Java 전체 192개 중 스키마 버전 기대값 1개를 수정한 뒤 해당 클래스 8개 재통과; PACS Python 50개 통과; 인증서 화면·팝업 출처 검증 15개 통과. 실제 Java/PostgreSQL/OpenBao/MariaDB 통합에서도 무초대 등록·활성화·자동 연결·비밀번호 세션 접근·판독문 서명까지 통과했습니다. SV70 전체 클라이언트 빌드는 별도 의존성 준비가 필요합니다.

V006은 기존 데이터를 보존하면서 PACS 계정의 고유 연결 키를 추가합니다. 적용 전 로컬 DB를 백업했고 런타임 스키마 6으로 갱신했습니다. 기존 관리자 등록 계정은 면허번호만으로 자동 이전하지 않습니다. [최초 등록 계약](../apps/backend/docs/PACS_SELF_ENROLLMENT.md)을 참고합니다.

아래는 10월 14일 기준의 기존 기능 검증 기록입니다.

인증서 등록·검증, PostgreSQL 영속 저장, OpenBao 서명 및 SV70 PACS 판독 승인 연동을 구현했습니다. 현재 실행 중인 내부망 서버는 합성 데이터용 개발 프로파일입니다.

## PACS 실행 구조

ID/PW 또는 공동인증서로 로그인합니다. ID/PW 사용자는 판독문 최종 승인 시 동일 사용자 공동인증서 재인증을 수행합니다. PACS 사용자와 INVIZ Doctor ID, 의사면허번호를 확인하고, 정확한 판독문에 대한 명시적 승인과 실제 서명 검증 후 A/RA로 저장합니다.

[실행 흐름](PACS_EXECUTION_FLOW.md), [PACS 연결 정보](PACS_LAN_CONNECTION.md), [서버 실행](LAN_TEST.md)을 참고합니다. 원본 SV70 전체 클라이언트 빌드는 React 등 외부 의존성 미설치로 검증되지 않았습니다. 별도 인증 팝업 모듈의 출처·창·난수 검증과 정리 동작은 확인했습니다.

## 운영 적용 전 남은 작업

- 실제 PACS 서버·웹 주소 확인, 인증 팝업 허용 출처 설정, 배포 코드·DB 적용 및 원격 판독 PC 검증.
- PC 공동인증서 SDK, 모바일 인증기관 및 ARS/TOSS/PASS·SMS 제공자 계약과 실제 API 연결.
- 운영 OIDC issuer/subject, DB TLS·권한·복구, HTTPS OpenBao와 키 관리·백업·복구 절차 구성.
- 운영 CA 신뢰체인·폐지 검증, 보존 정책·외부 감사 저장, 장애 및 부하 검증.

개인 로그인·등록/해제·인증서 종류·고객 구분·본인확인 수단 화면은 구현했으며, 공급자가 미설정이면 본인확인 성공이나 최종 등록 완료를 표시하지 않습니다.

현재 Java 영속 저장은 V005의 `certi_rt` 스키마를 사용합니다. V001~V004의 `certi` 도메인 스키마와 구분되며, `certi_rt`의 RLS는 운영 보강 과제로 남아 있습니다. 서비스 토큰 24시간 유효기간과 동일 호스트 OpenBao unseal 자료 보관은 내부 시험용 설정입니다.
