# 검증 시험과 운영 출시 기준

시험은 성공 경로뿐 아니라 권한·원본·승인·외부 장애 경계가 유지되는지 확인한다. 아래 표는 시험 계획이며 실행 결과는 로그와 리포트에 별도 기록한다.

## 필수 시험

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| AUTH-T01 | 실명·면허·소속 검증, 반려·재심사 | 근거·심사자·시각·사유 기록, 승인 전 서명 불가 |
| AUTH-T02 | 정상 MFA, 유휴·만료·새 기기·위험 | 정상 건별 OTP 없음; 위험 재인증, 무효 권한 차단 |
| SIGN-T01 | 명시적 승인·중복 클릭·동시 요청 | 지정 의사만 승인, 논리 결과 하나 |
| SIGN-T02 | 1바이트 변경·버전 교체·nonce 재사용·만료 | 실행 차단 또는 검증 INVALID |
| SIGN-T03 | FINAL 후 정정·재서명 | V1·서명 보존, V2·수정사유·새 승인 |
| SEC-T01 | 타기관 API·DB·객체 접근, pool 재사용 | 조회·쓰기·다운로드 차단, 정보 누출 없음 |
| SEC-T02 | 개인키 추출·DB/로그/백업 탐색 | 비수출, 키 원문 없음 |
| SEC-T03 | 관리자 직접 호출·Core 승인 위조·replay | 독립 승인 없으면 HSM 사용 불가 |
| SEC-T04 | 계정 복구·MFA 초기화·권한 철회 경합 | 단독 대리서명 불가, 허가 이전 철회 차단 |
| SEC-T05 | 악성 PDF·SSRF·로그 민감정보·개발 옵션 | 차단·마스킹·운영 startup 거부 |
| PKI-T01 | 갱신·폐기·CRL/OCSP stale/UNKNOWN | 신규 서명 차단 또는 증거 대기, 과거 기록 유지 |
| VERIFY-T01 | 잘못된 TSA imprint·체인·서명값·증거 누락 | INVALID와 INDETERMINATE 구분 |
| VERIFY-T02 | 만료·폐기·키 교체 후 과거 서명 | 당시 증거·정책으로 재검증, 현재 상태 별도 표시 |
| AUDIT-T01 | 중간 변경·삭제·끝부분 절단 | 독립 checkpoint 대조로 탐지 |
| INT-T01 | ACK 유실·중복·거절·재전송 한도 | 중복 업무 방지, ACKED 또는 DEAD_LETTER |
| UI-T01 | 역할·기관 변경·연타·오류·키보드 | 승인 제한·캐시 정리·정확한 상태 표시 |
| OPS-T01 | Worker kill·DB/Storage/HSM/TSA 장애·복원 | 유실·중복 완료 없음, 불명 결과 조정 |
| PERF-T01 | 50req/s 30분·일10만 건 분포 | 목표 latency와 큐 회복, 자원 한도 확인 |

SQL, API, 브라우저, 외부 공급자 시험을 층별로 실행한다. mock 검증은 암호학적 유효성 시험에 포함하지 않는다. skip은 통과가 아니다.

## 성능과 복구 목표

문서 업로드를 제외한 승인 접수 p95 500ms 이하, 정상 외부 공급자에서 서명·증거 완료 p95 5초 이하를 목표로 한다. 병원 ACK는 별도 지표다. 평균 PDF 500KB 가정과 실제 크기 분포를 각각 시험한다.

초당 50건은 접수 목표이며 HSM의 실제 TPS가 이를 충족한다는 뜻이 아니다. HSM/TSA가 느리면 큐·동시성·허용량을 측정하고 운영 용량을 재승인한다. 피크 종료 후 큐 적체가 계속 증가하면 실패다.

DB는 RPO 5분·RTO 4시간을 초기 목표로 한다. 완료 응답한 문서·증거는 별도 내구 저장·복제로 보존하고 복원 시 DB와 불변 manifest를 대조해 빠진 메타데이터를 복구한다. 이 절차를 실제 시험하기 전에는 완료 결과 무손실을 보장하지 않는다.

## 관측과 장애 대응

지표: 승인 성공·거부, HSM/TSA 지연, 서명 상태별 체류시간, 큐 깊이, DB pool, 인증서 만료 30/14/7일, CRL/OCSP 갱신, ACK 지연, 감사 checkpoint 누락, backup 실패.

HSM 장애 시 신규 실행을 멈추고 승인 만료를 존중한다. TSA 장애는 기존 서명을 재생성하지 않고 증거만 재시도한다. 전송 장애는 완료 서명을 유지하고 목적지별 circuit breaker를 사용한다. 감사 보존이 불가능하면 서명 완료를 확정하지 않는다.

운영자는 correlationId로 추적하고 환자 원문을 로그에 출력하지 않는다. DEAD_LETTER 재개는 사유와 작업자를 기록한다. RECONCILIATION_REQUIRED를 수동 성공 처리하려면 공급자 결과·원본 해시·서명 검증 증거가 필요하다.

## 출시 게이트

- 실제 HSM의 의사별 비수출 키·승인 통제·복구·성능 검증.
- 실제 SMS·TSA·CA 상태 서비스와 병원 1곳 이상 계약 시험.
- 법무의 시행 조문·보존기간·위탁·자체 CA 신뢰계약 검토.
- 보안 담당자의 Critical/High 결함 해소 확인.
- 실제 backup 복원과 증거 대조·누락 복구 훈련.
- 운영 profile에서 mock·개발 OTP·dev header·개발 CA 차단.
- 인비즈 책임자의 암호·권한 정책과 배포 승인.

인증 취득·법적 적합성·운영 성능을 코드 작성만으로 선언하지 않는다. 관련 외부 자료는 [[11_외부의존성_결정대장]]에서 관리한다.
