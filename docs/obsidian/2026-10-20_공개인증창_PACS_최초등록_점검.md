# 공개 인증 창에서 PACS 최초 등록 점검

## 확인된 사실

- 사용자 오류 창의 호스트는 `vision-certi.web.app`이다. 공개 API는 `prod`/PostgreSQL `READY`이며 인증서 신뢰 앵커와 CRL이 설정되어 있다.
- 이 PC의 Saintview PACS 개발 API는 공개 운영 서버가 아닌 `127.0.0.1:18082`를 사용하고, 팝업 설정은 `https://192.168.45.160:5184`, 기관은 `demo-hospital-a`다. 공개 운영 API의 기관은 `inviz`다. 두 DB의 인증서 등록 내역은 공유되지 않는다.
- `CERTIFICATE_NOT_ENROLLED`는 인증서 비밀번호 오류가 아니라 현재 팝업이 연결한 인증 서버에서 해당 지문이 활성 등록되지 않았다는 뜻이다. 최초 등록에는 PACS 의사 계정의 ID/PW 확인, 인증서 개인키 서명, 면허·자격 정보 및 동의가 필요하다. 심사 전에는 `PENDING`으로 저장되며 로그인 권한을 발급하지 않는다.

## 코드 수정 및 검증

- Saintview PACS의 공동인증서 버튼은 서버가 비밀번호 확인 후 일반 PACS 토큰을 발급하는 설정에서도 첫 등록을 시작한다. 등록 뒤 같은 계정의 인증서 재확인이 성공해야 그 토큰을 브라우저 로그인 저장소에 기록한다.
- PACS 프런트엔드 빌드 및 테스트 166개 통과. 등록 시작→활성 계정 연결→인증서 재확인 백엔드 테스트 2개 통과. 이 PC의 Vite 개발 서버가 수정된 프런트엔드 모듈을 제공하는 것도 확인했다.
- Saintview PACS 커밋 `ba62a58`, Vision-Certi 연동 문서 커밋 `79e0310`을 각 작업 브랜치에 푸시했다.

## 아직 확인할 부분

- 오류가 발생한 PACS 창의 실제 origin과 인증 창의 `#` 뒤 경로를 확인해야 그 PACS 배포본의 팝업 허용 목록, API 주소, 기관·HMAC 클라이언트 설정을 점검할 수 있다. 외부 PACS 배포본에는 이번 Saintview 소스 수정이 자동 적용되지 않는다.
- 실제 의사 인증서로 공개 운영 DB의 최초 등록, 관리자 면허 심사, 활성화, PACS 로그인 완료까지의 종단 간 시험은 아직 수행하지 않았다. 인증서 비밀번호와 개인키는 의사 PC 밖으로 보내지 않는다.
