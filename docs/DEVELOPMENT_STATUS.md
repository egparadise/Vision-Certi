# 구현·검증 현황 — 2026-10-17

## 판독의사 직접 등록 및 매번 공동인증서 로그인

관리자 사전등록·초대코드 발급과 기존 초대 기반 등록 API를 기본 차단했습니다(`VISIONCERTI_ADMIN_INVITATIONS_ENABLED=false`). 관련 입력·발급·재발급 화면도 비활성화했습니다. 판독의사는 PACS에서 기존 계정을 확인한 뒤 본인의 공동인증서를 등록합니다. 신뢰체인·폐지 검증, 본인 동의, 인증서와 의사 신원·면허 연결 검토는 유지합니다.

등록 후에도 매번 공동인증서로 로그인합니다. 등록이 ACTIVE여도 비밀번호 세션은 일반 의사 PACS API에 진입할 수 없습니다. `vc1` 세션의 유효성·사용자·인증서 지문과 원격 등록 상태를 확인합니다. 비밀번호 세션은 최초 계정 연결·등록·인증서 로그인 전환에만 사용합니다. 10월 15일의 등록 후 비밀번호 로그인 정책을 대체합니다.

검증: Java 관련 테스트 53개와 bootJar 성공, 웹 전체 53개 통과(후속 문구 변경 관련 5개 재통과), TypeScript/Vite 빌드 성공, SV70 Python 53개 통과, 실제 SV70 React 게이트웨이 격리 검증 8개 통과. 실제 Java/PostgreSQL/OpenBao/MariaDB 통합에서 무초대 등록·활성화, 비밀번호 세션 차단, 인증서 로그인, 판독문 서명·A 상태 저장·재연결을 확인했습니다. 합성 시험용 CA를 사용하며 실제 인증기관 검증 완료를 의미하지 않습니다.

실행 서버 `https://192.168.45.160:5184`에 INVIZ 변경을 적용하고 정책 API 및 화면을 확인했습니다. 실제 PACS 서버 배포와 전체 SV70 클라이언트 빌드는 별도 환경에서 확인해야 합니다.

V006은 기존 데이터를 보존하면서 PACS 계정의 고유 연결 키를 추가합니다. 적용 전 로컬 DB를 백업했고 런타임 스키마 6으로 갱신했습니다. 기존 관리자 등록 계정은 면허번호만으로 자동 이전하지 않습니다. [최초 등록 계약](../apps/backend/docs/PACS_SELF_ENROLLMENT.md)을 참고합니다.

## PACS 실행 구조

판독의사는 공동인증서로 로그인합니다. ID/PW는 최초 계정 확인과 인증서 로그인 전환에만 사용합니다. PACS 사용자와 INVIZ Doctor ID, 의사면허번호를 확인하고, 정확한 판독문에 대한 명시적 승인과 실제 서명 검증 후 A/RA로 저장합니다.

[실행 흐름](PACS_EXECUTION_FLOW.md), [PACS 연결 정보](PACS_LAN_CONNECTION.md), [서버 실행](LAN_TEST.md)을 참고합니다. 원본 SV70 전체 클라이언트 빌드는 React 등 외부 의존성 미설치로 검증되지 않았습니다. 별도 인증 팝업 모듈의 출처·창·난수 검증과 정리 동작은 확인했습니다.

## 운영 적용 전 남은 작업

- 실제 PACS 서버·웹 주소 확인, 인증 팝업 허용 출처 설정, 배포 코드·DB 적용 및 원격 판독 PC 검증.
- PC 공동인증서 SDK, 모바일 인증기관 및 ARS/TOSS/PASS·SMS 제공자 계약과 실제 API 연결.
- 운영 OIDC issuer/subject, DB TLS·권한·복구, HTTPS OpenBao와 키 관리·백업·복구 절차 구성.
- 운영 CA 신뢰체인·폐지 검증, 보존 정책·외부 감사 저장, 장애 및 부하 검증.

개인 로그인·등록/해제·인증서 종류·고객 구분·본인확인 수단 화면은 구현했으며, 공급자가 미설정이면 본인확인 성공이나 최종 등록 완료를 표시하지 않습니다.

현재 Java 영속 저장은 V005의 `certi_rt` 스키마를 사용합니다. V001~V004의 `certi` 도메인 스키마와 구분되며, `certi_rt`의 RLS는 운영 보강 과제로 남아 있습니다. 서비스 토큰 24시간 유효기간과 동일 호스트 OpenBao unseal 자료 보관은 내부 시험용 설정입니다.
