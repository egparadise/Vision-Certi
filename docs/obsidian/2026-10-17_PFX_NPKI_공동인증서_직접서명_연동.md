# PFX/P12·NPKI 공동인증서 직접 서명 연동 (2026-10-17)

## 현재 실행 흐름

1. PACS 공동인증서 로그인 버튼은 설정된 INVIZ 인증 화면을 연다. 최초 인증이면 PACS ID·비밀번호로 계정과 면허번호를 확인한 후 의사가 인증서를 직접 등록한다. 등록 완료 후에는 로그인마다 새 일회용 인증 요청을 등록 인증서로 서명한다.
2. PC 화면은 PFX/P12 **또는** NPKI의 `signCert.der`와 암호화된 `signPri.key`를 선택하고 비밀번호를 입력한다. 서명 바이트는 HTTPS 화면을 실행하는 의사 PC에서만 처리한다. INVIZ 서버에는 공개 인증서, 필요한 중간 인증서, 서명값, 알고리즘만 전송한다.
3. INVIZ 서버는 인증서 신뢰체인·유효기간·CRL 폐지 상태·서명·등록 지문·의사 면허 및 소속 상태를 검증한다. 첫 인증은 계정 연결·동의·검토·활성화 후 PACS에 일회용 handoff를 발급한다.
4. PACS가 최종 판독 스냅샷을 만들면 의사는 정확한 원문과 해시를 확인한다. `GET /v1/doctor/sign-requests/{id}/certificate-payload`에서 받은 바이트에 같은 공동인증서로 직접 서명한다. 요청 바이트에는 테넌트, 서명 요청·문서·버전 ID, 보고서·검사 ID, SHA-256, 의사 ID, nonce, 검토 확인이 포함된다.
5. `POST /v1/doctor/sign-requests/{id}/approve`는 `documentSha256`, `nonce`, `reviewAttestation=REVIEWED_EXACT_REPORT_CONTENT`, `certificateDerBase64`, `externalSignatureBase64`, `externalSignatureAlgorithm`을 받는다. 서버는 등록 인증서 지문과 서명을 확인한 뒤 OpenBao 의사별 키로 판독문을 추가 서명한다. 두 증거는 감사기록과 함께 보관된다.

## 파일 형식과 검증 범위

| 형식 | PC 처리 | 서버 처리 |
|---|---|---|
| PFX/P12 | 암호 해제, 인증서·개인키 일치 확인, WebCrypto RSA-SHA256 서명 | 공개 인증서·서명·CA/CRL·계정 연결 검증 |
| NPKI `signCert.der` + `signPri.key` | PKCS#8 AES 또는 한국형 SEED-CBC/SHA-1 암호 해제, 키 일치 확인, RSA-SHA256 서명 | 동일 |

실제 PFX, NPKI AES, SEED-CBC/SHA-1 시험 파일을 생성해 서명 검증을 통과했다. 발급기관별 추가 암호화 OID, 인증서 용도, 중간 CA 및 CRL 배포 방식은 실제 의사 인증서로 별도 적합성 시험이 필요하다. 지원하지 않는 파일은 로그인 성공으로 처리하지 않는다. 개인키를 자바스크립트 메모리에서 완전히 지울 수 없으므로 공유 PC 사용과 브라우저 확장 프로그램 정책도 운영에서 통제해야 한다.

## 내부망 확인 및 운영 경계

- 웹: `https://192.168.45.160:5184/`; API: 웹의 `/v1` 프록시를 통해 로컬 `127.0.0.1:18082`에 연결한다.
- 웹 테스트 77개, PACS Python 테스트 53개, API 계약 2개 통과. 백엔드 전체 203개 중 이번 기능 관련 테스트 통과; 기존 DB 스키마 버전 6을 기대하던 테스트는 7로 정정해 개별 재검증했다.
- 현지 서버는 개발 프로파일과 시험용 CA/CRL이다. 운영 적용에는 실제 발급기관 CA·최신 CRL, 의료기관의 면허·소속 검토, TLS·OpenBao·DB·복구 설정 및 실제 PACS 서버/의사 PC 현장 시험이 필요하다. 검증 응답의 `clinicalUseAllowed=false`와 신뢰 시각 미제공 상태를 실제 의료법상 적합성 확인 없이 임상 승인으로 해석하지 않는다.
