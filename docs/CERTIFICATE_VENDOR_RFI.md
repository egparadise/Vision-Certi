안녕하세요. INVIZ의 의료인 인증·전자서명 관리 프로그램 Vision-Certi에 공동인증서 등록과 로그인 기능을 연동하려 합니다. 아래 요구사항을 지원하는 현재 판매 제품, 평가 SDK 및 라이선스, 기술 지원 범위와 견적을 요청드립니다.

## 1. 사용 목적

판독의사가 PACS 계정을 확인한 뒤 본인 소유 공동인증서를 직접 등록하고, 이후 로그인마다 공동인증서 인증을 수행합니다. 사용자 화면은 보안프로그램 설치 확인, 인증서 선택, 인증서 비밀번호 입력, 등록·로그인 결과로 구성합니다. 인증서 비밀번호는 보안모듈에서만 입력하며 개인키와 비밀번호를 INVIZ 서버로 전달하지 않습니다.

최초 등록 시 의사면허번호와 전문의 자격번호·전문과목을 수집하고 기관 담당자가 증빙을 검토합니다. 인증서 소유자와 의사 신원을 연결할 수 있는 검증 수단이 있으면 별도 안내 부탁드립니다. 공동인증서 인증 결과만으로 의료인 자격이 확인된다고 가정하지 않습니다.

판독문 서명은 별도의 INVIZ 승인 서버와 OpenBao 키 관리로 처리합니다. 이번 문의의 기본 범위는 기존 공동인증서의 등록·로그인과 인증서 검증입니다.

## 2. 연동 환경

| 항목 | 환경 및 확인 요청 |

| 웹 화면 | React·TypeScript·Vite, HTTPS |
| 인증 서버 | Java·Spring 기반, 서버 검증 모듈의 지원 JDK·OS·배포 제약 확인 요청 |
| PACS | SaintView SV70, Python 서버 및 웹/Electron 클라이언트 지원 방식 확인 요청 |
| 시험 환경 | 내부망 사설 IP·개발 HTTPS 도메인 사용 가능 여부와 라이선스 조건 확인 요청 |
| 운영 환경 | 병원·판독센터별 배포, 운영 도메인·기관 수·의사 수는 견적 협의 시 확정 |

보안프로그램의 로컬 통신 방식, 브라우저 권한 안내, 허용 origin 설정, 방화벽 요구, 프록시 환경, 설치 권한, 무인 설치·업데이트 지원 여부를 함께 알려주십시오. Electron에서 `file://` 또는 별도 애플리케이션 origin을 지원하는 경우 권장 통합 방식을 요청드립니다.

## 3. SDK와 서명 결과 요구사항

서버는 용도, 서비스 식별자, 계정·기관 연결 정보, 암호학적 난수, 만료 시각을 포함한 일회성 요청을 만듭니다. 브라우저는 서버에서 받은 정확한 바이트를 보안모듈에 전달합니다. 공급업체 SDK의 실제 메서드·반환 형식으로 연동할 예정이므로 아래 자료를 요청드립니다.

1. JavaScript 로더, PC 설치파일, 서버 검증 모듈, API 문서와 실행 가능한 등록·로그인 예제.
2. 모듈 설치·실행 확인, 인증서 선택, 서명 요청, 취소·오류·시간 초과에 대한 API와 오류 코드.
3. 원문 서명 지원 여부 및 결과 예제. 현재 서버는 공개 DER 인증서·중간 체인과 `SHA256withRSA` 또는 `SHA256withECDSA` 서명을 받습니다. 원문/사전 해시, 문자 인코딩, RSA 패딩, ECDSA 서명 인코딩을 명시해 주십시오.
4. PKCS#7/CMS SignedData 방식이면 detached/attached 여부, signed attributes, 원문 바이트 검증, 서명자 선택과 서버 검증 예제를 제공해 주십시오. 반환 구조에 맞춰 서버 구현 범위를 협의하겠습니다.
5. 테스트용 인증서·체인·폐지 검증 자료와 평가 라이선스. 실제 개인정보가 포함되지 않는 시험 자료를 요청드립니다.
6. 서명된 설치파일의 배포 주소·SHA-256, 코드서명 정보, 지원 버전·보안 업데이트 정책과 장애 지원 방식.

개인키·PFX·비밀번호·PIN을 웹 앱이나 INVIZ API로 전송하지 않는 흐름이어야 합니다. SDK 자체 인증서 선택창만 지원한다면 선택 결과·지문을 검증할 수 있는 연동 방법을 안내해 주십시오.

## 4. 인증서와 신원 검증 범위

지원 발급기관·인증서 종류·정책 OID·용도 제한, 타 기관 발급 인증서의 이용 조건, 인증서 갱신·재등록 처리 방법을 요청드립니다. 개인용 공동인증서를 의료 PACS 로그인에 사용할 수 있는 제품·서비스 이용 범위를 구체적으로 안내해 주십시오.

신뢰체인과 OCSP/CRL 검증의 클라이언트·서버 역할, 검증에 필요한 통신 대상, 캐시·갱신 주기, 폐지·unknown·통신 장애 시 처리, 응답 검증 예제와 과금 여부를 요청드립니다.

인증서 소유자의 신원과 등록 의사를 연결하는 서비스 또는 의사면허·전문의 자격 조회 서비스를 별도로 제공한다면, 제공기관·권한 요건·확인 항목·결과 식별자·계약·비용을 구분하여 안내해 주십시오. 지원하지 않는 항목은 미지원으로 표시해 주셔도 됩니다.
