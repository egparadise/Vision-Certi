# PACS SP10 설계 검토와 인증서버 반영

## 요청과 검토 범위

사용자가 지정한 `Web PACS/3.40.10` 폴더의 설계 문서, 서버 소스 패치, 빌드 보고서, 배포 명세와 ZIP 파일 목록을 검토했다. REA MCP는 현재 세션의 도구·리소스 목록에 연결되어 있지 않아 호출하지 못했다. 직접 소스 검토와 실행 테스트로 진행했으며 REA MCP 검토 결과라고 표시하지 않는다.

PACS 설치 실행 파일 내부 구현 전체를 검증한 것은 아니다. 제공 패키지에는 PACS helper 원본 전체가 없으며 실제 원격 PC의 설치·로그인·의사 인증서 입력은 이번 작업에서 실행하지 않았다.

## 발견 사항과 반영

| 사항 | 판단과 조치 |
| --- | --- |
| HMAC 키가 없는 원격 PC는 기존 서버 간 API를 교환할 수 없음 | SP10의 S256 + nonce 결합 요청, 공개 capabilities, PC redeem/status API 반영 |
| ZIP의 서버 기준 커밋은 `7131d3c`; 현재 운영 기준은 `00ce8b1` | 제공 JAR/dist를 덮어쓰지 않고 최신 소스의 기록 기능 위에 병합·재빌드 |
| 초기 handoff 제안은 JWT/JWKS, 구현 문서는 직접 HTTPS 교환 | 실제 SP10 계약인 `VC-PC-PROOF-S256-V1`로 확정; JWT 발행을 주장하지 않음 |
| 새 PC redeem/status의 잘못된 verifier 요청 기록 누락 | 비밀값 없이 PC_REDEEM/PC_STATUS 거절 감사 기록 추가 |
| SP10 제공 패치는 계정·PC·로그인·판독 이벤트 전송을 포함하지 않음 | 선택 clientInfo와 proof verifier로 보호하는 PC events API 추가. 실제 전송에는 PACS helper 추가 구현 필요 |
| 기존 HMAC 기록 기능과 혼용 위험 | 기존 API·중복 이벤트 처리·기관 범위·집계 유지. 3.40.6 전용 패치 버튼에 버전 명시 |
| 공개 PC verifier의 무기한 기록 제출 위험 | 교환 완료 + 2시간 이내 proof만 PC 이벤트 제출 허용; 인증 권한과 관측 기록 분리 |
| 기존 DB 행과의 호환 | nullable JSONB 필드만 추가. 기존 필드를 실제 제거한 테스트 행으로 HMAC 흐름 확인. V010 유지 |

PKCE S256 계산과 verifier 길이는 [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636.html)을 참고했다. 인증서 검증 정책, PACS 로그인 비밀번호 처리, DB·키·기관 설정을 변경하지 않았다.

## 입력 파일 확인

- `VisionCerti-PC-SP10.zip`: SHA-256 `785d451571effa60c67484e15655ddd5478755a4201ea84e1dd1a5e58b8eb948`
- `SaintViewPACS_3.40.10_x64-setup.exe`: SHA-256 `1cc553e465dbc5dc5b9105453d6c71a0a1c09b95b250e68bca29aa7f090fc238`
- 두 값 모두 제공 release-manifest와 일치. 서명자 신뢰 검증이나 설치 실행을 대신하지 않는다.
- 패키지 설치 스크립트/실행 파일을 실행하거나 현재 PACS 설치를 교체하지 않았다.

## 검증

- 서버 36개 테스트: 서비스 11, 메모리 HTTP 12, PostgreSQL HTTP 12, 공개 경로 1.
- 웹 22개 테스트: 인증 팝업 7, 기록 화면 3, 상태·이동 4, 관리자 모드 8.
- S256/nonce/audience 불일치, HMAC ↔ PC 코드 교차 교환, 재사용·만료, 동시 요청 중 한 번만 성공 확인.
- PostgreSQL 저장소 재연결 후 PC proof 유지와 필드가 없는 기존 형식의 challenge/proof 처리 추가 확인.
- 유효한 PC proof로 이벤트 제출, 중복 재전송 1회 집계, 승인 요청 횟수와 서로 다른 판독문 수 분리 확인.
- verifier·일회용 코드가 감사 기록 및 DTO 문자열에 노출되지 않음을 확인.
- 웹 운영 빌드와 Java bootJar/컨테이너 빌드 완료. 브라우저에서 서버 ON·대시보드·카드 키보드 이동 확인(격리 시험 데이터).
- 웹 번들 크기 경고는 기존과 동일하며 빌드는 성공했다.

## PACS 개발 측 전달

[PACS_PC_S256_연동](../PACS_PC_S256_연동.md)에 실제 요청/응답과 이벤트 규격을 정리했다. 원래 SP10은 인증서 검증·교환·상태 확인에 대응한다. 계정·PC 이름과 실제 로그인 성공/판독 요청은 helper에서 `/pc/events`를 호출해야 수집된다. 서버는 미전송 값을 만들어 내지 않는다. 기존 3.40.6 기록 패치를 SP10에 적용하지 않는다.

실제 원격 PC에서 최초 ID/PW+인증서 확인, 다음 인증서 단독 로그인, 최종 성공 화면, 판독 승인 전 상태 확인은 설치된 SP10과 실제 PACS 계정으로 최종 확인해야 한다.
