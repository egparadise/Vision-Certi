# PACS 공동인증서 확인 전용 API·웹 배포 보고

## 구현과 운영 상태

- 구현 커밋 `84ed60e`는 PACS 자체 ID/PW 인증 뒤 사용할 공동인증서 소유 확인 경로를 추가했다. 서버는 PACS ID/PW를 받지 않는다. 공개 인증서·서명·신뢰체인·유효기간·폐지 상태를 확인한 뒤 60초짜리 일회용 코드를 발급한다.
- PACS 서버는 HMAC 인증으로 코드를 한 번 교환하고 `verified: true`, `authentication: "Y"`, 인증서 SHA-256 지문, 확인 ID와 만료 시각을 받는다. 승인 시에는 확인 ID로 서버 상태를 재조회한다. MD/JSON 파일의 `Y` 값만으로 승인하지 않는다. 인증서 비밀번호·개인키는 의사 PC에 머물고, PACS 계정 비밀번호는 평문 MD/JSON에 기록하지 않도록 연동 계약에 명시했다.
- Cloud SQL PostgreSQL에 `V010__pacs_certificate_proofs.sql`을 적용했다. 운영 API는 Cloud Run `vision-certi-api-00010-lqc`이며 컨테이너 이미지 digest는 `sha256:1e819dd7617f38cc756994c590664003338e0bcef79079ff92f955b54fe2db98`이다. 이번 작업에서 동일 소스의 웹 빌드를 Firebase Hosting `https://vision-certi.web.app`에 다시 배포했다.
- 실제 공개 API 확인: `/v1/runtime/capabilities`는 `prod`, PostgreSQL `READY`, 스키마 V010, PACS 연동 가능 상태를 반환했다. `POST /v1/pacs-certificate-proofs/challenges`는 HTTP 201과 `PACS_CERTIFICATE_PROOF` 서명 대상을 반환했다. 웹 메인 페이지는 HTTP 200이며 배포된 자산은 `index-Usv4EVCa.js`다.

## 적용 범위와 남은 작업

- Vision-Certi 서버와 웹 팝업은 배포됐다. 이 PC의 설치형 SaintView PACS 3.3.46은 여전히 기존 `#/login`을 연다. PACS 소스에 새 `#/certificates/pacs-proof` 팝업, 일회용 코드 HMAC 교환, PACS 계정과 지문 연결, 이후 로그인과 Approve 시 상태 재조회가 반영되어야 실제 PACS 로그인 흐름이 바뀐다.
- 실물 공동인증서의 비밀번호 입력부터 PACS 로그인·판독 승인까지의 종단 간 시험은 아직 수행하지 않았다. 운영 API의 `clinicalUseAllowed`는 `false`다. 이 배포는 임상 사용 적합성 승인을 뜻하지 않는다.
- 자세한 요청·응답과 PACS 구현 절차는 [확인 전용 연동 문서](../PACS_공동인증서_확인전용_연동.md)를 따른다. 인증서 발급·폐지 확인과 PACS 계정 권한 검사는 서로 다른 책임이다.
