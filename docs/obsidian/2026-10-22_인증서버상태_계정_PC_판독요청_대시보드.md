# 인증서버 상태와 계정·PC·판독 요청 대시보드

## 반영 결과

- 상단 운영 배너에 **인증서버 ON / 연결 안 됨 / 확인 중** 표시. 실제 `/v1/health`를 30초마다 조회하며 5초 제한, 캐시 사용 금지, 화면 종료 시 요청 취소를 적용했다. API 연결 여부이며 임상 사용 허가와 구분한다.
- 등록 판독문 → 판독문 목록, 전자서명 완료 → 서명 내역, 전송 대기 → 전송 큐, 감사 이벤트 → 감사 로그로 이동한다. 키보드 Enter로도 작동하며 `i` 도움말은 화면을 이동시키지 않는다.
- 관리자 운영 대시보드에도 PACS 인증 현황을 표시한다. 계정·PC·IP 검색과 인증서별 인증 시도/성공, PACS 로그인 시도/완료/실패, 판독 승인 요청 횟수/판독문 식별 해시별 집계를 제공한다. 화면은 30초마다 갱신된다.
- 서버 기록과 PACS 보고 기록의 의미를 구분한다. 단순 인증 상태 GET 조회를 판독 요청 건수에 넣지 않는다.

## 저장·연동

추가 API: `POST /v1/integrations/pacs/certificate-proofs/{verificationId}/events`. HMAC 인증, 해당 PACS가 교환한 인증 ID와 기관 범위를 검증한다. `eventId`의 동일 내용 재전송은 중복 처리하고, 다른 내용으로 재사용하면 409로 거절한다. 기존 인증 및 감사 테이블을 사용하며 추가 DB 마이그레이션은 없다.

계정 ID/번호, PC 이름/설치별 UUID, 로그인·승인 요청 이벤트를 보관한다. 출처는 `PACS_REPORTED`이다. 서버의 접속 IP/전달 IP 및 인증서 지문·발급기관·만료 정보와 함께 관리자만 조회한다. 비밀번호, 개인키, HMAC/Bearer 토큰, 일회용 코드를 추가 기록하지 않는다.

원격 PC 패치에는 무결성 검증을 적용한 로컬 전송 대기 파일을 사용한다. 통신 실패 시 기록과 eventId를 보존하고 30초마다 재전송한다. 인증 만료 및 운영 행 삭제 후에도 해당 기관의 영구 코드 교환 기록을 근거로 지연된 감사 이벤트를 받을 수 있다. 인증 유효기간이나 접근 권한을 연장하지 않는다.

기존 PACS는 계정·PC 이름·로그인 완료·승인 요청을 보내지 않았다. 이 값들은 패치 적용 후부터 수집되며 과거 기록을 임의로 채우지 않는다. 로컬에서만 발생한 인증서 비밀번호 오류는 서버 검증 시도에 포함되지 않는다. 최초 report 번호가 없는 경우의 식별 범위는 패치 README에 명시했다.
