# Vision-Certi Frontend (`apps/web`)

Vision-Certi 의사 서명 검증 및 증명서 발급 관리 웹 인터페이스입니다. Vite, React, TypeScript, Tailwind CSS를 기반으로 구축되었습니다.

---

## 1. 실행 및 개발 환경

### 사전 요구사항
- Node.js 18+
- 백엔드 서비스 (`apps/backend`): 기본 포트 `http://127.0.0.1:8080`

### 개발 서버 실행
```bash
npm install
npm run dev
```
- 브라우저에서 `http://localhost:5173`으로 접속합니다.
- Vite 프록시(`vite.config.ts`)를 통해 `/api` 요청이 로컬 백엔드(`http://127.0.0.1:8080`)로 프록시됩니다.

### 목(Mock) 모드 vs 라이브(Live) 모드
- 상단 헤더 우측의 **모드 토글 스위치**를 통해 백엔드 API 통신(Live)과 브라우저 인메모리 시뮬레이션(Mock) 간 전환이 가능합니다.
- 백엔드가 실행 중이지 않은 상태에서도 전체 UI 흐름(문서 조회, PDF 미리보기 확인, 서명 승인/반려, 감사 로그 확인)을 테스트할 수 있습니다.

### 테스트 및 검증
```bash
# TypeScript 타입 검사
npm run typecheck

# 단위 및 통합 테스트 실행 (Vitest)
npm test

# 프로덕션 빌드
npm run build
```

## 2. 보안 및 인증 아키텍처 안내

### 개발/데모 모드 헤더 게이트 (`isDemoEnabled`)
- 로컬 개발 환경(`import.meta.env.DEV`) 또는 명시적 데모 환경 변수(`VITE_ENABLE_DEMO=true`)에서만 테넌트(`X-Tenant-Id`) 및 액터(`X-Actor-Id`) 전환 헤더가 전송됩니다.
- 프로덕션 빌드(`import.meta.env.PROD`)에서는 합성 신원 전환 UI가 차단되며, 운영용 IdP/SSO 및 실제 세션 쿠키/토큰 연동이 필요합니다.

### 서명 승인 전제조건 및 멱등성 보장
- **담당 의사 확인**: 로그인된 액터와 서명 요청의 대상 의사 ID가 일치해야 승인이 가능합니다.
- **PDF 열람 확인**: 의료진이 원본 진단서를 실제로 검토했음을 확인하는 체크박스를 체크해야 서명 버튼이 활성화됩니다.
- **단일 Idempotency-Key 유지**: 네트워크 타임아웃이나 재시도 시에도 동일 요청 건에 대해 하나의 멱등키를 유지하여 이중 승인/이중 발급을 방지합니다.
- **네트워크 모호성 해소**: 요청 실패 시 상태를 자동 조회하여 이미 백엔드에 반영되었는지 검증 후 재시도를 안내합니다.
- **최신 버전 및 해시 일치**: 문서 해시(SHA-256) 및 서명 요청 만료 여부를 검증합니다.

## 3. 한계점 및 법적 고지사항 (Limitations & Disclaimers)

1. **자체 운영 PKI 설계와 현재 구현**:
   - 자체 운영 PKI는 설계 목표이며, 현재 실제 CA·HSM·TSA는 연결되지 않았습니다.
   - 법적 적합성과 임상 사용 적합성은 확인되지 않았으며, 운영 도입 전 별도 검토가 필요합니다.
2. **모의 서명(Mock Signature)**:
   - 실제 개발 API 연결과 클라이언트 모의 모드 모두 개발용 모의 서명을 사용합니다. 개발 API의 HMAC 키와 저장 데이터는 메모리에만 존재합니다.
3. **임상 및 실제 의료 현장 사용 불가 (Not for Clinical Use)**:
   - 본 소프트웨어는 개념 증명(PoC) 및 아키텍처 검증을 위한 프로토타입이며, 실제 임상 현장 또는 법적 효력이 필요한 의료 증명서 발급 업무에 직접 사용할 수 없습니다.
